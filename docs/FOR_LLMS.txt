8. DEXMATE COMPETITION SETUP REPO — IMPORTANT CONFIRMED DETAILS
===============================================================================

Pinned:
  intelligent-control-lab/dexmate-setup
  4be4d16140b25f730673d664b49c58280b07ef46

Gripper CAN:
  can1
  1 Mbit/s
  Motor ID 1 = LEFT
  Motor ID 2 = RIGHT

Official driver shape:
  from gripper import Grippers
  g = Grippers()
  g.home()
  g.left.open()
  g.left.close()
  g.left.grip(current=0.6)
  g.right.grip(current=0.6)
  g.left.position()
  g.status()
  g.halt()
  g.release()
  g.close_bus()

Semantics:
  - Motor.grip() is the object-aware current-limited close operation.
  - grip() returns a dict including a boolean "gripped".
  - close() is position close and can stall against an object; do not use it as
    the normal object grasp primitive.
  - halt() stops motion WITHOUT losing the multi-turn reference.
  - release() sends motor-off and destroys the multi-turn position reference.
    Re-home after release/power loss.
  - home establishes closed reference; source docs say it may take ~1 minute.

Our gripper wrapper was fixed on Sep 27 after reviewing this repo:
  steadyhand/grippers/vega.py
  now supports scope left/right/both and per-side Motor.grip().
  VegaAdapter.verify_grasp() now consumes the returned "gripped" value.

URDF/model:
  organizer repo provides:
    docs/files/urdf/vega_1u_gripper.urdf
    docs/files/urdf/custom/vega_1u_gripper.urdf

Both contain modeling joints such as Lift and torso_flip even though live Vega
control exposes arms/head only. This creates an IMPORTANT modeling issue:
  Pinocchio needs values for any non-active movable joints in the selected
  kinematic chain.
  Source reference-data.json contains source-robot reference values, including
  Lift and torso_flip, but DO NOT blindly assume they match the competition unit.

EE / tip frames:
  provided URDFs contain L_ee / R_ee.
  custom gripper URDF also contains tip_l / tip_r.
  The actual control TCP to use for our pick/place policy must be chosen and
  physically verified. Do not assume L_ee is the jaw-tip TCP.

Source repo also includes calibrated/source reference transforms for:
  camera
  EE to gripper
  custom tip
  source-robot TCP
These are excellent starting references but are SOURCE_ROBOT_REFERENCE until
validated on the actual competition robot.

Pose/safety history from organizer repo:
  "rest"/pre_move and "brickbench_home" were used on the source robot.
  "folded" / "folded_closed_hand" are explicitly banned in source tooling because

The source goto_pose.py includes a coarse wrist-separation safety guard and

9. IMPORTANT CONTROL-SEMANTICS CONFLICT TO RESOLVE ONSITE
===============================================================================

This is a high-priority audit item.

Organizer Q&A/manual language:
  wait_time=0 is associated with real-time/continuous command usage and a
  100–500 Hz command loop.

Organizer-linked known-good source pose utility:
  software/poses/goto_pose.py
  calls:
    comp.set_joint_pos(..., wait_time=0.0)
  then sleeps WAIT (default 0.6 s) between bounded 0.12 rad steps.

Our current VegaAdapter:
  uses a POSITIVE wait_time for each set_joint_pos call:
    self._arm.set_joint_pos(waypoint, wait_time=wait)

Therefore:
  Do not assume our set_joint_pos timing semantics are correct merely because the
  Python signature exists.
  During DexMate training, ask the sponsor to explain:
    - what wait_time actually means
    - whether positive wait_time blocks/interpolates
    - whether the organizer goto_pose.py pattern is the recommended safe pattern
    - whether repeated step commands should use wait_time=0 + explicit sleep
  Then align VegaAdapter with the confirmed behavior.

This is currently one of the most important pre-motion code-review points.

17. ROBOTICS CONVENTIONS — DO NOT BREAK THESE
===============================================================================

Pose:
  position in metres
  quaternion order wxyz

Transform:
  T_destination_source
  p_destination = T_destination_source * p_source
  Example:
    T_base_camera maps camera-frame coordinates into base frame.

Joint values:
  radians unless authoritative API says otherwise.

Do not mix:
  simulator world coordinates
  camera coordinates
  robot base coordinates
  object coordinates
  TCP coordinates

For physical grasp geometry prefer:
  T_base_tcp = T_base_part * T_part_tcp

Do not use:
  "object xyz + hardcoded world offset"
as the final general solution when orientation changes matter.

IK:
  q -> FK -> TCP pose
  desired TCP pose -> IK -> q

Always remember:
  one Cartesian pose can have multiple IK branches.
  Seed choice matters.
  returning to a consistent home/ready q can improve repeatability.

18. STRATEGY / PERFORMANCE PRINCIPLES
===============================================================================

Competition scoring rewards completed tasks, not elegant software.

General principles:
  - reliability > speed until reliability is high
  - speed only matters as a tie-breaker according to Q&A
  - protect already-working parts
  - isolate layers during debugging
  - do not debug perception + IK + gripper + insertion simultaneously
  - log every trial
  - keep known-good rollback commits/configs
  - if a hard part repeatedly threatens the rest of the sequence, prefer safe
    recovery/skip over jamming and losing easy points

Desired failure behavior:
  grasp failed
    -> retract
    -> retry once
    -> if still failed, safe skip/continue if rules/sequence allow

  insertion excessive contact
    -> retract
    -> recenter/search
    -> do not push harder blindly

Open-release parts should become boring/repeatable before spending large amounts
of time on USB/HDMI/bolt/pin insertion.
